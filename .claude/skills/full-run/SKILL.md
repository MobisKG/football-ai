# Полный прогон: новые видео → статистика на сайте

Устройство и обоснование этапов — `docs/PIPELINE_v2.md`. Здесь порядок действий
и что делать, когда что-то ломается.

## Перед запуском проверь

1. **Где запускать.** По умолчанию — на сервере: `python -m full_run.remote start`.
   Тогда прогон переживает закрытый ноутбук. Если сервер недоступен, скажи об
   этом пользователю и предложи запуск с ноутбука (`python -m full_run.run`) —
   он будет зависеть от связи ноутбука.
2. **Ключи.** `football/.env` → `KEY=` (RunPod), `~/Documents/sport/.env` →
   `SPORTX_TOKEN`/`SPORTX_USER`/`SPORTX_PASS`. Токен сайта протухает; модуль
   `full_run.site` сам логинится заново, если есть логин и пароль.
3. **Машин быть не должно:** `GET https://rest.runpod.io/v1/pods` → `[]`.
   Если что-то висит от прошлого раза — удали, прежде чем начинать.
4. **Деньги.** Скажи пользователю оценку до аренды (её печатает этап плана) и
   держи `--max-usd`. Оценка для 24 игр по 2 на машину: 12 машин, ~2–2,5 ч, ~20–25 $.

## Запуск

```bash
cd football/scripts
python -m full_run.run --dry-run            # только план: какие видео новые, сколько машин и денег
python -m full_run.run --per-pod 2          # полный прогон с ноутбука
python -m full_run.remote start --per-pod 2 # то же, но на сервере (предпочтительно)
```

Этапы идут сами: план → качалка → раздача → разбор → сбор и загрузка. Состояние
в `<outdir>/state.json`, перезапуск той же командой продолжает с места обрыва.
Отдельный этап: `--stage plan|download|fanout|collect`.

## Пока идёт

- Следи `python -m full_run.remote log` или `tail -f <outdir>/run.log`.
- **Не жди молча.** Любое ожидание — с пределом времени; если сеть пропала,
  в журнале появится «СЕТЬ ПРОПАЛА».
- Докладывай пользователю по этапам: сколько скачано, сколько машин работает,
  сколько игр загружено. Не обещай сроков точнее, чем ±30 минут.

## Что ломается и что делать

| Признак в журнале | Причина | Что делать |
|---|---|---|
| `Sign in to confirm` у качалки | YouTube блокирует адрес машины | Скрипт сам меняет качалку до 4 раз. Если и это не помогло — запусти этап заново позже, адреса выдаются другие |
| `установка не удалась` на рабочей машине | сорвалась установка (сеть хоста) | Машина удаляется сама; повтори `--stage fanout` — он создаст замену только для непокрытых игр |
| игра осталась `cpu_failed` | процессорные шаги на машине упали | Забери `out/<игра>.cpu.log` с машины, почини скрипт, повтори игру: `--stage fanout --only <игра>` |
| `нет match_guid` в загрузке | игра не сопоставлена с матчем сайта | Впиши `match_guid` в `<outdir>/plan.json` и повтори `--stage collect`. Автоматически его взять неоткуда: у текущей учётной записи нет списка матчей |
| `цвет хозяев не определён` | `home_side.py` не уверен | Это защита: на сайт такое не грузится. Разбери руками по `kits_sheets/`, потом догрузи `upload_analytics.py` |
| разбор тихо умер через ~30 мин | OpenBLAS на 96 ядрах | Уже закрыто ограничением потоков в `run_gpu_match.sh`; если повторилось — проверь, что переменные `*_NUM_THREADS` дошли до машины |
| машина не отвечает | хост RunPod пропал | Сторож на машине удалит её через 2,5 часа молчания. Повтори игру этапом `fanout` |
| на счету чужая машина | её создала другая задача | Не трогай. Прогон удаляет только свои машины, их id в `state.json` |

Чинить код — можно и нужно: правки коммить в `football` (ветка main). В
`sportx` (ветка develop) без отдельной просьбы не пушить: там автодеплой.

## После прогона

1. Проверь машины: `GET /v1/pods`. Там могут работать машины **других задач**
   (разметка поля, скорости) — сноси только машины своего прогона
   (`delete_run_pods(state)`), а перед сплошным сносом `sweep_pods()` спроси
   пользователя. 16.09 сплошной снос убил чужую работавшую машину.
2. Отчёт `<outdir>/REPORT.md`: по каждой игре — скачано, разобрано, загружено.
3. Скажи пользователю: сколько игр на сайте, что не загружено и почему, сколько потрачено.
4. Что не загрузилось по содержательным причинам (нет составов, не разделяются
   команды, не прочитаны номера) — перечисли, не выдавай за успех.

## Границы

- Скорости и пробег этот прогон не считает: для них нужна разметка поля
  (`pitch_marker`, `pitch_speed_game.py`), см. `docs/PROMPT_autocalib.md`.
- Ничего не грузи на сайт, если `home.json` не уверен или статистика не прошла
  проверки. Лучше пустая графа, чем неверная.
