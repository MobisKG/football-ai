## Правила

- Арендованные машины RunPod: ключ в `football/.env` строкой `KEY=`.
  Образ `runpod/pytorch:2.4.0-py3.11-cuda12.4.1-devel-ubuntu22.04`,
  cloudType SECURE, порт 22/tcp, ключ `~/.ssh/id_ed25519_personal`.
  **Каждую машину удалять сразу после её работы**, а в конце убедиться,
  что `GET https://rest.runpod.io/v1/pods` возвращает `[]`. Если машина
  не получила IP/порт за 7 минут или CUDA не инициализируется —
  удалить и создать с другим типом GPU (это уже случалось).
- Нагрузка на маки умеренная (`nice -n 15`), долгое время допустимо.
- Никаких ожиданий вида «пока не появится файл» без ограничения по времени
  и без выхода при недоступной машине: каждый цикл ожидания — с лимитом
  и с проверкой, что машина ещё отвечает.
- Токен API сайта: строка `SPORTX_TOKEN=` в `~/Documents/sport/.env`
  (папка вне git). Это токен пользователя лиги, им разрешена загрузка.
- Ничего не пушить в `sportx/develop` — оттуда идёт автодеплой.
  В `football` коммитить и пушить можно.
- В отчёте писать честно: что упало, что пропущено, сколько денег ушло.

## Шаг 0. Ускорение (до запуска всего, ~1 час)

1. `extract_crops2.py`: 5 снимков на трек вместо 8; треки короче 3 с
   пропускать. Проверить на `results/gz_real91`: пересчитать голосование
   только по первым 5 снимкам из `numbers.json` и сравнить состав с
   текущим `stats.json` — если потеряно больше 1–2 номеров из 36,
   оставить 8.
2. `reid_osnet.py`: снимки в модель пачками по 64 на GPU.
3. `scoreboard.py`: `--step 10`.
4. `run_gpu_match.sh`: скачивание видео и все шаги в одном скрипте,
   каждый шаг пропускается, если результат уже есть (уже так). Пробный
   прогон одной короткой игры (Fc shicko 2-й тайм, 17:45) на машине —
   убедиться, что цепочка проходит без вмешательства. Замерить время.

## Шаг 1. Сопоставить видео с матчами в базе

API `https://cp.sportx.kg/v1` с заголовком `Authorization: Token ...`:
- команды: `team/?page_size=1000` (одноимённые команды бывают из разных
  сезонов — брать ту, у которой матч 13-го сезона от 13–14.09.2026);
- матчи команды: `match/team?team_guid=`;
- карточка: `match/detail/?match_guid=` (без токена) — там кто хозяева,
  а кто гости, и `playing_field`.

Для каждого видео найти match_guid по названиям команд и дате. Два видео
без названия (42:08 и 37:35 от 14.09) и игры с одной командой в названии
(ДОЛОН, ШАЛТА, DOS ATLETIK, ТЕННИСИ 8:33) — сопоставить по табло в кадре
(`scoreboard.py` читает названия команд) или отложить и перечислить в
отчёте. Игру Fc shicko vs 90-Ынтымагы, выложенную двумя таймами, разобрать
как два видео и сложить в одну загрузку.

Записать таблицу видео → match_guid → хозяева/гости в
`results/batch_2026-09-14/matches.json` до запуска.

## Шаг 2. Прогон

Управляющий скрипт `scripts/batch_run.sh` (написать) на мак мини:
- создаёт 4 машины (типы на выбор: A40, RTX A5000, L40S, RTX 4090;
  при ошибке — другой тип), на каждой ставит зависимости один раз;
- раздаёт видео по машинам очередью; на машине: скачать → `run_gpu_match.sh`
  → упаковать `pos.json ball_cands.json numbers.json osnet.json
  scoreboard.json crops/tracks.json` → скачать на мак мини в
  `~/football-ai/batch/<имя>/`; при падении шага — повторить один раз,
  затем пометить видео как неудачное и идти дальше;
- на мак мини после каждого видео: маковские шаги из таблицы выше,
  `stats.txt` и `stats.json`;
- определить, какой цвет формы — хозяева: по табло (`scoreboard.json`
  → `teams`, верхняя строка = team 1) и по цветовой полоске нельзя, поэтому
  правило: сравнить названия из табло с названиями хозяев/гостей из
  карточки матча; цвет команды берётся из `team_names` в `pos_final.json`
  и из того, у кого больше игроков с формой этого цвета. Если сомнение —
  не загружать, оставить на утро с пометкой;
- загрузить `upload_analytics.py`, проверить чтением
  `GET match/analytics?match_guid=`;
- удалить машины, когда очередь пуста; в самом конце проверить список
  машин ещё раз;
- в конце написать `~/football-ai/batch/REPORT.md`: по каждому видео —
  статус, счёт по табло и счёт судьи из карточки (должны совпадать),
  владение, число игроков с номерами, время машины; общая сумма аренды;
  что не загружено и почему.

Ожидание: ~15 ч видео × ~2,3 мин/мин ≈ 35 ч машинного времени, на 4
машинах ≈ 9 ч, ~17–20 $ (после ускорения ~12–13 $).

## Известные ловушки (подробнее в STATE.md)

- `tail -2 файл1 файл2` в Linux — ошибка; с `set -e` она роняет скрипт.
- `pkill -f run_gpu_match` убивает и дочерние процессы, если шаблон
  совпадает с ними; использовать `[r]un_gpu_match`.
- Табло вместе с двумя YOLO не помещается в 48 ГБ видеопамяти — табло
  запускать после них.
- Модель отвечает «10», не видя цифр, и читает номер с соседа — это уже
  учтено в `apply_numbers.py` (проверка цвета формы на каждом снимке,
  вес «10» и «1» 0,3).
- YouTube с некоторых адресов машин может не отдавать видео: тогда
  повторить на другой машине; качать через мак — крайний случай (часы).
